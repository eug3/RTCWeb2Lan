# 项目结构

本仓库包含**两个部署单元**。两者通过信令配对后建立 P2P 直连，公网侧只做发现与兜底。

```
                          公网                         内网
                 ┌─────────────────────┐      ┌──────────────────────┐
   浏览器 ──────►│  fdn（front desk node）│      │ tunnelagent           │
                 │  静态页 + 信令 + 兜底   │      │  出站连信令 + 反代      │
                 └─────────────────────┘      └──────────┬───────────┘
                        ▲                                 │
                        └──── P2P DataChannel ────────────┘
                              （业务流量直达，不过公网）
```

---

## 1. `fdn` — front desk node（公网边缘）

**职责**：前端"前台"。浏览器接触到的第一站，也是 P2P 打不通时的兜底通道。

| 组成 | 说明 |
| --- | --- |
| 静态资源 | Service Worker、连接页、holder、SPA 静态文件 |
| 信令服务 | 在房间内转发 SDP/ICE，**只做发现，不转发业务流量** |
| 兜底反代 | 隧道不可用时，把请求按路由表反代到内网，站点仍然可用 |

**对外端口**：静态 `:8080`、信令 `:8787`（`/__lan/ws`）。

> 兜底目前有两种落地形态，二选一即可：
> - **容器内置**：fdn 自己按路由表反代（自包含，不依赖宿主机配置）；
> - **宿主机 nginx**：由前置 nginx 完成 `/api/` 反代。
>
> 目标是收敛成前者，让 fdn 成为完整的可交付单元。

## 2. `tunnelagent` — 内网代理（内网侧）

**职责**：部署在内网，主动出站连接信令（**不监听任何端口**），收到浏览器请求后按路由表转发到内网服务。

| 组成 | 说明 |
| --- | --- |
| 信令客户端 | 连上房间，等待 offer 并应答 |
| 隧道接收 | 每条 HTTP 请求一条 DataChannel |
| 反向代理 | 按 `routes.yaml` 选择目标，HTTP/1.1 原样转发 |
| 会话维持 | 按目标维护 cookie jar |

## 当前目录 → 目标目录

现在代码是**混在一个仓库里、按技术分层**的。目标按**部署单元**分层：

| 现在 | 目标 | 说明 |
| --- | --- | --- |
| `src/`、`index.html`、`connect.html`、`holder.html`、`vite.config.ts`、`tsconfig.json`、`public/` | `fdn/web/` | 浏览器侧全部前端 |
| `agent/cmd/web2lan-signal/`、`agent/internal/signaling/server.go` | `fdn/signal/` | 信令服务端 |
| `agent/cmd/web2lan-agent/`、`agent/internal/tunnel/`、`agent/internal/signaling/client.go` | `tunnelagent/` | 内网代理 |
| `agent/internal/protocol/` | 两边共用 | 信令消息定义，双方都依赖 |
| `scripts/docker-entrypoint.sh`、`Dockerfile` | `fdn/` | 只服务公网容器 |
| `routes.yaml` | `tunnelagent/` | 内网路由表 |

### 拆分前必须先解决的一件事

`agent/` 目前是**单个 Go module**，而 `tunnelagent` 同时依赖 `signaling/server`（fdn 的）与 `signaling/client`（自己的）。要真正拆成两个项目，需要：

- **方案 A（推荐）**：保持一个 module、两个 `cmd/`，只在**目录**上按部署单元归位。改动最小，构建仍然一条命令。
- **方案 B**：拆成两个 Go module（`fdn` 与 `tunnelagent`），`protocol` 提到公共 module 或各留一份。彻底独立，但要处理 module 依赖与版本。

**在拆分落地前，本文档代表目标结构，现有代码位置以仓库实际为准。**

## 与浏览器的契约

| 路径 | 归属 | 说明 |
| --- | --- | --- |
| `/__lan/sw.js` | fdn | Service Worker（scope `/`） |
| `/__lan/connect.html` | fdn | 连接页 |
| `/__lan/holder.html` | fdn | 常驻 iframe |
| `/__lan/config.json` | fdn | 运行时配置 |
| `/__lan/ws` | fdn | 信令 WebSocket |
| `/api/*` | tunnelagent（经隧道）| 命中 `apiPrefixes` 且不在 `neverTunnel` 内 |
| 其余 | 源站 / 兜底 | 静态资源与认证接口 |
