# 如何测试

## 方式一：一键本地栈（假内网服务，最稳）

```bash
pnpm run dev:stack
```

打开输出里给出的 URL：

```
http://127.0.0.1:5273/?signal=ws%3A%2F%2F127.0.0.1%3A8787%2Fws&room=demo
```

等三行状态都变绿（Service Worker / 数据面 / WebRTC 已连接），点下面的按钮。

验证点：

- 响应 URL 里**不能出现内网 IP**
- 返回内容里有 `HELLO-FROM-INTRANET-SERVICE`
- 状态行显示 `P2P 直连`，不是 `经 TURN 中转`

## 方式二：对接真实内网服务（推荐）

前置：本机已在 EasyTier 网络内（能 `curl 10.1.1.230:9011` 通）。

```bash
# 终端 1：信令
./.dev-bin/signal -addr 127.0.0.1:8787

# 终端 2：Agent，指向真实 Sense
./.dev-bin/agent -signal ws://127.0.0.1:8787/ws -room real \
    -target http://10.1.1.230:9011

# 终端 3：页面
npx vite --port 5273
```

打开：

```
http://127.0.0.1:5273/?signal=ws%3A%2F%2F127.0.0.1%3A8787%2Fws&room=real
```

验证点：

- `/tunnel/154/health` 应返回真实健康检查 JSON
- 用浏览器打开 `/tunnel/154/` 能看到**完整的 Sense 页面**

## 方式三：换任意内网服务

只改 Agent 的 `-target`，其余不变：

```bash
# 230 的 Sense
./.dev-bin/agent -signal ws://127.0.0.1:8787/ws -room r1 -target http://10.1.1.230:9011

# 12 号机 DSH Web（需带 token）
./.dev-bin/agent -signal ws://127.0.0.1:8787/ws -room r2 -target http://10.1.1.12:3080

# Workflow Gate
./.dev-bin/agent -signal ws://127.0.0.1:8787/ws -room r3 -target http://10.1.1.1:3000
```

页面地址相应改 `&room=r1` / `r2` / `r3`。

## 用命令行直接验收（不打开浏览器）

```bash
# Go 单测：Agent 转发 + 信令配对
pnpm run test:go

# TS 单测：路由 / HTTP 编解码 / 分片 / 数据面
pnpm test

# 浏览器端到端（需 dev 栈在跑）
node scripts/e2e-real.mjs       # 假内网
node scripts/e2e-intranet.mjs   # 真实 230 Sense
```

## 测试时要盯住的三件事

1. **状态行是 `P2P 直连` 还是 `经 TURN 中转`** —— 后者说明打洞失败。
2. **响应 URL 里有没有 `10.1.1.x`** —— 有就是地址泄露，属于失败。
3. **内容是不是真实服务返回的** —— 用 `build_id` 这类会变的字段来证明，
   不要只看 200。

## 已知会失败的情况

| 现象 | 原因 |
| --- | --- |
| 打不开任何页面 | SW 未激活，或先开了内网页再开初始化页 |
| 请求超时 504 | Agent 没在跑，或信令房间号对不上 |
| 返回 404 | 请求路径与 `-target` 后面的服务不匹配 |
| 页面空白 / JS 报错 | 内网页面依赖 WebSocket，SW 无法代理 |
| 每次刷新都要重连 | 设计如此：WebRTC 连接绑定页面 JS |
